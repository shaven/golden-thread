1. The core idea

Claude's context window resets after every session. Golden Thread moves what you learn out of the session and into a structured vault on disk — before the session ends. The vault is an Obsidian folder tracked by git. The right slice of it is loaded at the start of every session.

The promotion ladder

Every fact lives at the narrowest scope that is honest and is promoted upward only when a second project proves it general.

session conversation
↓ /gt:gt-work
Projects/<slug>/memory/*.md ← this project, this detail
↓ /gt:gt-promote
research.md · decisions.md ← settled findings and choices
↓ /gt:gt-promote
Knowledge/ ← true for several projects
↓ /gt:gt-promote
global-memory/ ← true in every session, everywhere
↓ /gt:gt-promote (with hook wiring)
core-rules/ ← enforced via hooks, not merely stored

Facts move up as they prove general. They never move back down. Retiring a fact sets status: stale and records what superseded it — the file stays on disk.

The Core-rule tier

Above global-memory/ sits the Core-rule tier. These are rules enforced via hooks wired into ~/.claude/settings.json (UserPromptSubmit + Stop hooks) — they are re-asserted every session, not just stored as files. /gt:gt-init installs these hooks automatically.

Stored ≠ enforced
A rule in core-rules/ with no wired hook is inert — it looks correct and does nothing. /gt:gt-lint reports this as core-unenforced. Treat it as a real defect; never suppress it.

Loading is lazy, by design

/gt:gt-open reads the project's core docs and then reads memory/MEMORY.md only — one line per file. Memory files load on demand. A project with 70 notes costs ~80 lines to open instead of ~2,000. The one-line description in MEMORY.md is the entire basis for deciding whether a file is worth loading.

The discipline
Promote a fact only when a second project proves it general. When in doubt, file it narrow — promotion is cheap, demotion isn't.

2. Installation

Requirements: Python 3.8+, Claude Code installed and running.

Option A — Clone from GitHub

git clone git@github.com:shaven/golden-thread.git
cd golden-thread/golden-thread-plugin
bash install.sh

Option B — Install from zip

unzip golden-thread-plugin.zip
cd golden-thread-plugin
bash install.sh
Important
Restart Claude Code after install. The /gt: skills register at startup only and will not appear until you do.

What the installer does

Two plugins are installed into Claude Code's plugin cache:

  • gt — memory, projects, session workflow, enforcement hooks
  • gt-wiki — knowledge base with immutable sources
~/.claude/plugins/cache/golden-thread-plugin/gt/0.9.5/
  .claude-plugin/   ← plugin metadata
  hooks/            ← enforcement hook scripts
  scripts/          ← vault_init.py, gt_lint.py, gt_settings.py, …
  skills/           ← /gt:* skill definitions (14 skills)
  templates/        ← vault scaffold templates

Updating

# after git pull or downloading a new zip:
bash install.sh

Each version installs into its own subdirectory; newer versions do not conflict with older ones.

Uninstalling

rm -rf ~/.claude/plugins/cache/golden-thread-plugin

Your vault and ~/.claude/vault-config.json are unaffected.

3. First-time setup

/gt:gt-init — Initialize the vault

Run once per machine. Claude will ask:

  1. "Do you already have an Obsidian vault on this machine?"
    • Yes → provide the path. Golden Thread adds only missing files; existing notes are untouched.
    • No → choose a path (default: ~/Documents/Obsidian/GoldenThreadVault). Obsidian is optional — the vault is plain Markdown and works without it.
  2. "What's your domain or team name?" — e.g. "Acme CloudOps" or "Platform Engineering"

The script writes ~/.claude/vault-config.json, scaffolds the vault, and installs Core-rule enforcement hooks into ~/.claude/settings.json. Idempotent — safe to re-run.

For a vault that predates the Core-rule tier:

python3 $SCRIPTS/vault_init.py install-core-rules --vault ~/my-vault
Note
CLAUDE.md is read at session start. Rules added mid-session apply from the next session — that is not a bug; restart to pick them up.

/gt:gt-create — Scaffold a new project

InputNotes
SlugMust match the folder name; lowercase, hyphens only
TitleHuman-readable name
DomainCoarse grouping, e.g. "platform", "data"
TopologyWhere the code lives — see §4
Sub-project parentOptional; slug of the parent project
RunbookWhether to scaffold runbook.md

After scaffolding, Claude fills idea.md from your description. idea.md is immutable once written — the traceable "why".

/gt:gt-ingest — Import an existing project

Copies notes and memory files into the vault. Never moves or deletes originals.

Wikilink trap
Renaming files destroys [[wikilink]] graphs. Measure first: 
grep -roh '\[\[[^]]*\]\]' --include='*.md' . | wc -l
Prefer keeping filenames. Never repoint links inside Sources/.

4. Vault layout

<vault>/
  CLAUDE.md              Conventions and page schema
  index.md               Navigational index of all Knowledge pages
  log.md                 Append-only audit trail
  review-queue.md        Items flagged for owner review
  lint-declines.md       Suppressions with reasons

  Sources/               IMMUTABLE — never modified after creation
  Knowledge/             Cross-project wiki pages
  global-memory/         Loaded into every session
    MEMORY.md            Index — what actually gets read at session start

  Projects/
    CONVENTIONS.md       Stages, properties, domain taxonomy
    PROTOCOL.md          Cross-project process rules
    INFRASTRUCTURE.md    Server fleet — defined ONCE, linked from projects

    <slug>/
      README.md          Status board + YAML frontmatter
      source.md          Where the code lives; deploy topology
      idea.md            Origin story — IMMUTABLE
      research.md        Append-only dated findings
      decisions.md       Append-only numbered ADRs
      design.md          Current architecture — rewritten in place
      spec.md            Handoff artifact (when design complete)
      runbook.md         Operational procedures (optional)
      memory/
        MEMORY.md        Index — the ONLY file gt-open reads
        <topic>.md       Loaded on demand

Project folder anatomy

FileMutabilityPurpose
idea.mdImmutableThe "why" — never changed after creation
source.mdUpdatedCode location, deploy topology, file plan
research.mdAppend-onlyDated findings and gotchas
decisions.mdAppend-onlyNumbered ADRs
design.mdRewrittenCurrent architecture — always describes NOW
spec.mdCreated onceHandoff artifact with acceptance criteria
runbook.mdAppend / updateOperational procedures and landmines
memory/*.mdUpdated per sessionSession state; carries level/enforcement frontmatter

Source topology

TopologyMeaning
localFolder on this machine. No deploy step.
remoteOne repo, one server. Server pulls from GitHub.
bastion-jumpSeveral servers via one gateway host.
bastion-directSeveral servers, each independently reachable.

Bastion topologies carry a file plan: each deployed file is marked static (byte-identical everywhere) or unique (per-server; never cross-deployed). The fleet is defined once in Projects/INFRASTRUCTURE.md — never copied into a project file.

5. Daily workflow

/gt:gt-open my-project   # load context, see where you left off

# ... work happens ...

/gt:gt-work              # write back findings before closing

/gt:gt-open <slug> — Start a session

Reads CONVENTIONS.md and PROTOCOL.md once per session, then the project in order:

source.md → idea.md → research.md → decisions.md
          → design.md → spec.md → runbook.md
          → INFRASTRUCTURE.md (bastion topologies)
          → memory/MEMORY.md   # index only; files load on demand

If research.md exceeds ~200 lines, reads headings first and only loads targeted sections. Announces the review-queue item count if non-zero. Summarises stage, topology, hosts, next action, blockers, and which memory files exist but are unloaded.

/gt:gt-work — End a session

The step most people skip — and skipping it is what causes the vault to decay.

DestinationWhat belongs there
research.mdNew findings, dated. New discoveries only.
decisions.mdNumbered ADR with context and rejected alternatives. Stable choices only.
design.mdRewritten in place when architecture changed. Describes now.
runbook.mdOperational commands and known landmines.
memory/*.mdSession state, updated in place.
spec.mdCreated when design is complete enough to hand off.

Memory files carry frontmatter to make durability explicit:

metadata:
  type: core | feedback | user | reference
  level: core | context | generic      # default: generic
  enforcement: validated | reminder    # required only for level: core

Default to generic. Do not set level: core in gt-work — Core is a promotion that requires wiring a hook, which is gt-promote's job.

After writing, gt-work asks whether any finding applies beyond this project and should be promoted. It also updates stage:, topology:, and domain: in README.md frontmatter when the project's reality changes.

/gt:gt-query — Ask the vault a question

Reads index.md, follows wikilinks 2–3 hops into Knowledge/, falls back to grep. Be specific. If a result shows status: stale, verify it before acting.

6. Context & verification

/gt:gt-farm — Route work to external AI

Routes bulk, mechanical, or second-opinion tasks out of this context to an external AI service. The unit is a work packet: a self-contained Markdown document with a strict FINDINGS / GAPS return contract. Transport is swappable — paste into a web UI today; a script sends it to an API later. The packet is identical either way.

All four gates must pass before a task leaves. Any failure means the work stays here.

GateQuestion
StatelessAnswerable with no vault or repo state?
Self-containedFits in a paragraph plus a list of URLs?
CheckableVerifiable without redoing the work?
ReleasableEvery input safe to hand a third party?
Releasable is default-deny
Never include: account identifiers, balances, hostnames, internal IPs, credential locations, non-public source code, or personal identifiers. Check this gate while building the packet, not before sending it.

Key rules:

  • One packet, one task. A packet asking three questions returns three half-answers.
  • Supply a vocabulary block with exact model IDs and product names read from the system — never from memory. A stale prior produces a stale query.
  • Results come back as unverified. Promote only after opening the source: URL and confirming the claim.
  • GAPS is mandatory; GAPS: None must be justified, not asserted.
  • Cite the specific page carrying the claim — never a homepage or section index.

Packets are saved to <vault>/Projects/external-ai-tools/packets/YYYY-MM-DD-slug.md for auditability.

/gt:gt-validate — Verify claims by re-deriving

Verifies a claim by re-deriving it, not by reviewing the reasoning that produced it. Give a validator your reasoning and it grades the argument — and inherits the same blind spot. Give it only the claim, the rules, and the artifact, and it must go back to primary sources.

Use before recording a finding as fact, before a production change, or when a number matters.

Validator classes

ClassUse when
empiricalA number, measurement, or result could be wrong
vantageThe measurement position may not be able to observe the answer
rule-complianceWork must satisfy core-rules/ or CONVENTIONS.md
codeCode may not do what its name, comment, or docs claim

Build the packet with exactly three fields: claim, rules, artifact. Strip all conclusions, confidence signals, and adjectives that imply the expected answer. If it says "confirm that X", rewrite it as "determine whether X".

Outcomes: confirmed / refuted / cannot-verify. cannot-verify is never a pass — name what was missing. Append the verdict to research.md. A refutation supersedes the original finding.

7. Knowledge management

/gt:gt-promote — Graduate a finding

The judgement call: has a second project proved this general?

From → ToWhen
memory/ → research/decisionsFinding stopped changing session to session
project → Knowledge/A second project hit the same truth
Knowledge/ → global-memory/Needed in every session, every project
any → Core tierRule must be enforced, not just stored — gt-promote wires the hook

Nothing is deleted. Retiring sets status: stale and records the superseding fact.

/gt:gt-refresh — Update sources

Checks Sources/ for upstream changes. Creates a new immutable file with supersedes: — never edits the old one. Knowledge pages citing the old source are flagged for update.

Where does this fact go?

The factGoes to
"This preset is wrong right now"memory/
"This API rejects plural keys"research.md
"We use POST for all mutations, and why"decisions.md
"The system is structured like this now"design.md
"This platform behaviour bit two projects"Knowledge/
"Always diff before overwriting prod"global-memory/
"How to restart the prod backtest"runbook.md
"Never scp without backing up"PROTOCOL.md
"This code lives on host X at path Y"source.md
"Which box serves which role"INFRASTRUCTURE.md
Two failure modes
Too narrow: a platform truth buried in one project — the next project rediscovers it the hard way.
Too wide: a quirk in global-memory/ loading into unrelated sessions as a rule that isn't true there.

When unsure, file narrow. Promotion is cheap; demotion isn't.

8. Maintenance

/gt:gt-lint — Health checks

CheckWhat it catches
index-gapKnowledge page not in index.md — gt-query won't find it
broken-link[[wikilink]] resolving to nothing
orphanKnowledge page linked from nowhere
memory-unlistedmemory/*.md not in MEMORY.md — Claude will never load it
global-gapglobal-memory/*.md not in its index
memory-bloatglobal-memory/ file over 30 lines
global-scope-leakProject-specific content in global-memory/
superseded-citedKnowledge page citing a superseded source
staleKnowledge page marked status: stale
source-todosource.md with no topology or deployment targets
frontmatterProject README missing properties, or slug ≠ folder name
core-misplacedA rule declares level: core but lives outside core-rules/
core-no-enforcementlevel: core with no enforcement field declared
core-unenforcedThe declared enforcement hook is not actually wired
Never suppress core-unenforced
This is the machine-checkable form of "rule stored but never asserted". Suppressing it recreates the original bug with a paper trail saying it was fine.
Fix: vault_init.py install-core-rules --vault <vault>

Triage workflow

  1. You broke it — fix now
  2. Already broken — record in review-queue.md; don't guess at a target
  3. False positive — suppress in lint-declines.md with the reason

/gt:gt-settings — Automatic behaviour

View and toggle everything Golden Thread does without being asked.

SettingValuesDefaultWhat it does
component_updatesoff · report · confirm · autoreportAt session start, compares installed hooks/scripts against plugin source and reports drift
report_cardoff · minimal · fullminimalAt /compact, summarises session hygiene
 
python3 $SCRIPTS/gt_settings.py show            # current state
python3 $SCRIPTS/gt_settings.py explain <name>  # reasoning behind the default
python3 $SCRIPTS/gt_settings.py set <name> <value>

/gt:gt-runbook-lint and /gt:gt-review

gt-runbook-lint finds procedures duplicated across runbooks and routes them to the right shared layer: PROTOCOL.md, a Knowledge page, or a repo CLAUDE.md.

gt-review scans Obsidian daily notes for uncaptured tasks and ideas, then promotes selected ones into tracked projects.

9. Knowledge wiki (gt-wiki)

The gt-wiki plugin adds a structured knowledge base with immutable sources. Every ingested document is stored verbatim in Sources/ and never modified. Knowledge pages are synthesized summaries that link back to the originals.

Setup and usage

/gt:gt-wiki-init                          # initialize
/gt:gt-wiki-ingest <url or file path>    # add a source
/gt:gt-wiki                               # query
/gt:gt-wiki-lint                          # health check
/gt:gt-wiki-refresh                       # check sources for upstream changes

Page format

---
title: Page Title
category: concept | tool | runbook | decision | reference
tags:
  - lowercase-hyphenated
sources:
  - "[[Sources/filename.md]]"
created: YYYY-MM-DD
updated: YYYY-MM-DD
status: seed | growing | mature | stale
---
Cross-links are the navigation layer
Claude follows [[wikilinks]] hop by hop from index.md. Link bidirectionally. Cross-domain links (A ↔ B from different areas) are the most commonly missed and the most valuable for multi-hop questions.

10. Script reference

SCRIPTS=~/.claude/plugins/cache/golden-thread-plugin/gt/0.9.5/scripts

vault_init.py

# Fresh vault
python3 $SCRIPTS/vault_init.py fresh \
  --vault ~/my-vault --domain "My Team"

# Create a project
python3 $SCRIPTS/vault_init.py create-project \
  --vault ~/my-vault \
  --name my-project --title "My Project" \
  --tags "backend,api" --domain platform \
  --topology bastion-direct --runbook

# Create a sub-project
python3 $SCRIPTS/vault_init.py create-project \
  --vault ~/my-vault --name sub-feature \
  --parent my-project --domain platform

# Connect an existing vault to a new machine
python3 $SCRIPTS/vault_init.py connect --vault ~/existing-vault

# Install Core-rule enforcement hooks (for older vaults)
python3 $SCRIPTS/vault_init.py install-core-rules --vault ~/my-vault

gt_ingest.py

python3 $SCRIPTS/gt_ingest.py ~/Projects/my-project --json

gt_lint.py

python3 $SCRIPTS/gt_lint.py ~/my-vault \
  --queue ~/my-vault/review-queue.md

gt_settings.py

python3 $SCRIPTS/gt_settings.py show
python3 $SCRIPTS/gt_settings.py explain component_updates
python3 $SCRIPTS/gt_settings.py set report_card off

11. Troubleshooting

SymptomCause & fix
"vault-config.json not found"Run /gt:gt-init
Skills not showing after installRestart Claude Code. Skills register at startup only.
A rule in CLAUDE.md is ignoredRead at session start only. Rules added mid-session apply next session. Run /hooks or restart.
Memory files aren't loadingBy design — gt-open loads on demand. Ask for the file by name.
A memory file is never offeredRun /gt:gt-lint — likely memory-unlisted.
gt-query can't find a page you addedLikely index-gap. Add the page to index.md.
Core rules apply inconsistentlyRun /gt:gt-lint and look for core-unenforced. Fix: vault_init.py install-core-rules --vault <vault>
Timestamp missing from responsesEnforcement hook unwired. Run /hooks or re-run install.sh.
Want to turn off the session reportRun /gt:gt-settings set report_card off
Lint suppression isn't workingPaths are matched case-insensitively. Use the path exactly as lint reports it.
"conflict: vault-config.json points to a different vault"Run vault_init.py connect --vault <new-path>
